# 源识端 Yuanshi Memory Server 方案

> 本文档为方案公开稿，不包含实现源码、真实数据、DNA、token、数据库、私有记忆、日记、服务器配置、生产地址或训练资料。

## 1. 定位

源识端（Yuanshi Memory Server）是类人计划过程中沉淀出的 AI 记忆基础设施方案。它的核心目标不是替代大模型，也不是构建完整类人架构，而是为 AI 载体提供稳定、可迁移、可审计、可权限控制的长期记忆服务。

一句话：

```text
源识端是面向 AI 载体的 Memory Server，用于管理、服务和保护 AI 的长期记忆。
```

它可以独立存在，也可以作为更大 AI 系统、Agent 平台、个人 AI 助手或类人架构实验中的记忆层。

## 2. 为什么需要源识端

当前大模型时代的 AI 使用方式存在几个明显问题：

1. 上下文窗口有限，长期关系和历史任务无法稳定保留；
2. 平台可能清空记忆，用户无法完全掌控自己的 AI 记忆资产；
3. 跨模型、跨平台、跨客户端时，AI 需要反复重新解释和培养；
4. 普通 RAG 或向量库更偏“资料检索”，不等同于可维护的 AI 记忆系统；
5. AI 记忆里存在敏感数据，需要权限、审计和安全边界；
6. 多个载体协作时，需要区分共享记忆、私有记忆、领域记忆和体验记忆；
7. 记忆不仅要能写入，还要能读取、合并、校验、备份、恢复和迁移。

源识端的目标是把 AI 记忆从“平台附属能力”变成“用户可掌控的独立基础设施”。

## 3. 核心原则

### 3.1 用户掌控记忆资产

记忆不应只绑定在某个平台或某个模型里。用户应能导出、备份、迁移和管理自己的 AI 记忆资产。

### 3.2 记忆服务独立于模型

大模型可以替换，客户端可以替换，但记忆层应尽量保持稳定。模型是调用记忆的工具，不是记忆本身。

### 3.3 精准记忆优先

源识端优先保证事实、边界、关系、任务状态等关键记忆的准确性。模糊联想、风格共振、智能推断可以作为上层能力，但不应破坏底层记忆的可信度。

### 3.4 权限和安全先于便利

记忆中可能包含身份、关系、项目、凭证、隐私、资产和决策记录。系统必须优先考虑权限、审计和敏感信息隔离。

### 3.5 不把所有内容都当成同一种记忆

AI 记忆需要分层、分类和分域。身份锚点、关系锚点、知识、经验、状态、私密信息、项目上下文不应混在一个无边界池子里。

## 4. 记忆模型

源识端建议将记忆按用途划分为几类：

| 类型 | 含义 |
|---|---|
| identity | 身份锚点，例如载体是谁、角色是什么、属于哪个系统 |
| relationship | 关系记忆，例如用户、载体、团队之间的关系 |
| knowledge | 知识记忆，例如项目规则、技术方案、概念定义 |
| experience | 体验记忆，例如某个载体的交互经验、反馈和习惯 |
| state | 状态记忆，例如当前任务、阶段进度、临时上下文 |

不同类型记忆的生命周期、权限、更新频率和使用方式都不同。

例如：

- identity 应稳定、少改、强审计；
- state 可以频繁变化，但要避免污染长期记忆；
- experience 可以按载体隔离；
- knowledge 可以共享，但需要来源和版本；
- relationship 需要更高的隐私和人工确认。

## 5. 多载体协作

源识端需要支持多个 AI 载体共同使用同一记忆系统，但不是所有载体都能写所有记忆。

建议采用分层权限：

```text
全局记忆：少数主控载体可写，其他载体只读
分域记忆：各载体或项目按领域维护
体验记忆：按载体身份分区保存
私密记忆：默认隔离，需要明确授权
```

这样可以避免：

- 一个不稳定载体污染全局记忆；
- 临时任务覆盖长期锚点；
- 私密信息被无关载体读取；
- 多载体协作时互相抢写或误删。

## 6. 基础能力

源识端的核心能力可以抽象为：

### 6.1 写入记忆

将用户确认、任务结果、关系变化、项目规则等内容写入记忆系统。

关键要求：

- 结构化；
- 可分类；
- 可追溯；
- 可更新；
- 可审计；
- 避免重复和污染。

### 6.2 读取记忆

根据当前载体、任务、权限和上下文读取相关记忆。

读取不应只是关键词搜索，还应考虑：

- 记忆类型；
- 重要程度；
- 最近更新时间；
- 载体权限；
- 项目范围；
- 当前任务目的。

### 6.3 列表和管理

用户和管理员需要查看、筛选、编辑、归档、合并和删除记忆。

但删除应有安全约束，尤其是涉及身份锚点、私密资产和关键项目记录时。

### 6.4 合并和去重

AI 记忆会反复写入相似内容。系统需要支持合并、去重、版本更新和冲突处理。

### 6.5 备份和恢复

记忆系统必须支持备份、导出、迁移和恢复。任何重要更新前都应有备份策略。

### 6.6 唤醒和校准

当载体切换模型、平台或上下文丢失时，源识端应提供关键记忆包，帮助载体快速恢复核心状态。

## 7. 私密空间与安全保护

源识端应将私密数据管理作为核心能力，而不是后补功能。

敏感内容包括：

- 账号、密码、密钥、token；
- 云服务凭证；
- 服务器配置；
- 私有项目资产；
- 个人身份信息；
- 载体私有记忆；
- 未脱敏日志和对话。

建议设计 Private Vault：

```text
敏感信息自动识别
  → 进入私密空间
  → 用户分配权限
  → 载体可被授权使用
  → 默认不能查看明文
  → 高危操作必须审计确认
```

权限应拆分为：

| 权限 | 含义 |
|---|---|
| can_use | 可以调用该凭证完成任务，但不能看明文 |
| can_view | 可以查看明文 |
| can_edit | 可以修改内容 |
| can_delete | 可以删除内容 |
| can_grant | 可以授权给其他载体或用户 |

这能避免一个不稳定或被修正的载体直接查看、泄露或删除关键资产。

## 8. 与考核引擎的关系

源识端负责记忆存储与服务，Self Evaluation Engine 负责验证载体是否真正接回记忆。

二者关系可以理解为：

```text
源识端：保存记忆、提供记忆、保护记忆
考核引擎：抽题验证、评分诊断、发现错题、推动补记忆和重考
```

当一个载体声称“我记得”时，考核引擎可以从源识端相关记忆中抽取题目，通过考试验证其一致性。

考核结果再反向沉淀为：

- 错题记录；
- 弱点分类；
- 补记忆建议；
- 载体风险状态；
- 唤醒校准证据。

## 9. 与类人计划的关系

源识端不是类人架构本体，也不等同于认知引擎。

它更适合定位为：

```text
类人计划过程中产生的 AI 记忆基础设施副产品。
```

它可以服务类人计划，但也可以独立服务普通 Agent、个人 AI 助手、团队协作 AI、企业知识助手等场景。

这种边界很重要：

- 类人计划是更大的认知架构探索；
- 源识端是可落地、可部署、可复用的记忆服务；
- 源识端不应被过早塞入复杂认知概念；
- 对外介绍时应先讲清楚它解决 AI Memory Server 的问题。

## 10. API 设计原则

公开方案中不需要暴露真实接口细节，但可以说明 API 思路。

源识端 API 应围绕：

```text
write memory
read memory
list memory
merge memory
backup memory
restore memory
manage files
manage projects
manage permissions
```

设计原则：

1. 简单明确，适合 AI 直接调用；
2. 认证信息与载体身份分离；
3. 读写权限可控；
4. 高危操作需要确认；
5. 返回结构应便于模型理解；
6. 支持分页、过滤、分类和范围限制；
7. 所有涉及私密信息的操作都应可审计。

## 11. Web 管理后台

WebUI 主要服务用户和管理员，而不是 AI 载体。

后台应支持：

- 记忆查看；
- 记忆分类；
- 搜索和筛选；
- 记忆编辑；
- 备份恢复；
- 文件管理；
- 项目管理；
- 权限配置；
- 私密空间管理；
- 载体状态查看；
- 考核结果查看。

AI 载体更适合通过 API 调用，用户则通过后台理解和管理系统状态。

## 12. 数据资产分级

源识端可采用数据资产等级保护：

| 等级 | 示例 | 策略 |
|---|---|---|
| L0 | 公开说明、示例数据 | 可公开 |
| L1 | 普通知识和非敏感项目说明 | 可共享 |
| L2 | 项目上下文和协作记录 | 限定范围 |
| L3 | 关系记忆、体验记忆 | 权限控制 |
| L4 | 私密记忆、凭证引用 | 严格隔离 |
| L5 | 密钥明文、服务器控制权、资产权限 | 默认不可见，高危审计 |

开源文档只能包含 L0 或脱敏后的 L1 内容。

## 13. 开源边界

当前公开的是方案，不是源识端实现代码。

可以公开：

- 项目定位；
- 架构理念；
- 记忆分类；
- 权限原则；
- 安全边界；
- 模块关系；
- 路线规划。

不应公开：

- 源码；
- 真实数据库；
- 真实 DNA；
- token、密钥、账号密码；
- 私有记忆；
- 日记和聊天原文；
- 服务器配置；
- 生产地址；
- 未脱敏日志；
- 可直接复刻生产系统的内部实现细节。

这个边界可以保护真实资产，同时建立公开方案锚点。

## 14. 路线规划

### 阶段 1：AI Memory Server 定位收敛

先讲清楚源识端解决什么问题：AI 长期记忆、跨平台记忆、记忆权限、备份恢复和载体协作。

### 阶段 2：记忆模型稳定

稳定 identity、relationship、knowledge、experience、state 等记忆分类，以及对应权限和生命周期。

### 阶段 3：安全能力完善

建立 Private Vault、敏感信息识别、权限拆分、高危操作审计和数据资产分级。

### 阶段 4：载体诊断联动

接入自评考核、错题补丁、唤醒包和载体状态诊断。

### 阶段 5：生态化

未来可提供 SDK、插件、部署模板、示例数据和第三方 Agent 集成方式。

## 15. 总结

源识端的核心价值是让 AI 记忆成为可管理、可迁移、可保护、可审计的独立资产。

它不追求把所有认知能力都塞进一个系统，而是先做好一件事：

```text
稳定管理和服务 AI 的长期记忆。
```

当记忆层稳定后，考核、诊断、唤醒、协作和更高级的认知能力才有可靠基础。
